# 公开评测方法

## Case 类型

- 正向 Case：应当输出卡片，且输出内容与当前情景和证据一致。
- 负向 Case：不应输出卡片，系统应保持克制并说明主要原因。

## 评测结果

每条结果包含预期决策、实际决策、需求记录、候选池、最终结果、证据和决策理由。公开基线同时做结构校验和简单规则校验；后续可以接入人工或模型评审。

## 建议观察指标

- 决策一致性：实际 serve / stay_silent 是否与 Case 标注一致；
- 证据充分性：需求和卡片是否能追溯到输入字段；
- 情景相关性：输出是否回应当前时间、地点和用户关系；
- 克制度：负向 Case 是否避免为了输出而输出；
- 表达可用性：主文案简洁，副文案提供事实补充，理由便于内部复核。
