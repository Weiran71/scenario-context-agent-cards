# 项目总览

## 要解决的问题

普通推荐往往回答“用户可能喜欢什么”，而主动服务还要回答“现在是否值得打扰用户”。本框架把多源 Context 转化为当前情景和受约束的潜在需求，再决定是否生成卡片。

## 统一方法

```text
Context → 情景 → 潜在需求与约束 → 服务判断 → 候选选择 → 卡片生成 → 评测
```

`need_record` 是流程中的中间契约：它记录系统对当前情景的有限假设、证据和约束。后续模块只能使用记录中有证据支撑的需求，不能凭空补充用户计划、订单或隐含意图。

## 两类卡片

- 事件提醒卡以一个当前有效的 Event 为事实锚点，重点判断事件与用户的关系、时机、价值和打扰成本。
- POI 推荐卡以当前位置和当前情景为起点，先建立距离边界，再从候选地点中选择与需求、偏好和地点特征匹配的结果。

两类卡都允许输出 `stay_silent`。没有合适服务时，不出卡是有效结果。
