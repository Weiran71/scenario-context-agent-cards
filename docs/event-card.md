# 事件提醒卡公开流程

## 输入

事件卡读取用户偏好、常驻/到访状态、当前时间、天气、城区和一个合成 Event。Event 需要包含主题、状态、距离、关系度、事实描述和可执行动作。

## 处理顺序

1. 将时间、天气、地点和用户关系翻译为情景。
2. 检查 Event 是否当前有效。
3. 检查距离和用户关系是否足以形成服务价值。
4. 任意关键条件不满足时输出 `stay_silent`。
5. 全部满足时生成主文案、副文案、Action 和 Icon。

## 边界

事件卡不能使用用户未提供的行程、订单或导航目的地，也不能把地点排行榜类内容当作事件事实。公开基线只演示通用事件类型，具体商业分类需要在独立项目中重新设计。
